# Campus+ performance audit — 2026-10-23

Scope: measure, rank, fix and re-measure the fastest wins that do not change
product behaviour, routing, permissions or the design language. Everything below
was produced in this repository against the **local performance harness**; no live
production measurement was possible from the audit environment (see
[What could not be measured](#what-could-not-be-measured)).

---

## 1. What could not be measured

| Item | Status | Why |
|---|---|---|
| Lighthouse (any route, mobile or desktop) | **Not run** | The audit environment has no browser binary (no Chromium/Chrome, no Playwright cache). Lighthouse is a browser product; there is no supported headless substitute. |
| FCP / LCP / CLS / TBT / INP / main-thread work / long tasks / hydration cost | **Not measured** | All of these are browser-lab or field metrics. None is inferred from server timings in this report, and none is presented as a Core Web Vitals result. |
| Live production (Vercel) LCP/INP/CLS, P75 field data, Vercel Speed Insights | **Not available** | The repository contains no production deployment URL, and `pccoe.in` currently fails TLS negotiation (`ERR_SSL_UNRECOGNIZED_NAME_ALERT`). A handshake failure says nothing about React or rendering; it is an availability problem and is recorded only as such. Whether Speed Insights is enabled on the live project could not be verified. |
| Third-party tag / analytics cost | **Not applicable** | No analytics, tracking or third-party scripts are installed, and none were added. |

The numbers below are real measurements of this repository's code, taken on an
isolated harness with seeded fixture data. They describe **server render time,
request counts and transfer sizes**, which are the layers this task could move
and verify. They are not, and must not be read as, user-perceived loading
performance on a phone.

---

## 2. Method and environment

* App: `next start` (Next.js 16.3.8, Turbopack build) on `127.0.0.1:3100`.
* Supabase replacement: the repo's stub (`scripts/dev/perf/stub.mjs`) in front of a
  disposable PostgreSQL 17 cluster (`embedded-postgres`, port 55433), serving 25
  migrations and the seeded fixture set (12 accounts, 8 communities, 240 posts,
  420 messages, 142 notifications).
* Every upstream request costs **25 ms simulated RTT**; the stub records an exact
  trace per request (`/__perf/trace`), so request counts and per-query latencies
  are observed, not estimated.
* Client payload tool: `scripts/dev/perf/assets.mjs` (new in this audit). Parses the
  rendered HTML of each route, takes the modern (non-`noModule`) scripts,
  `modulepreload` and stylesheet links, and sizes each asset raw and gzip
  (zlib level 9). `next start` serves no `content-encoding`, so the gzip figures
  are *computed*; Vercel serves brotli, which would be slightly smaller.
* Runner: `npm run perf:measure -- --runs 5` — median of 5 requests per route after
  one warm-up request.
* Fixture user: the harness `student` account, signs in with a real session cookie
  issued by the stub. No production credentials, cookies or student data are used
  anywhere.

**Noise floor.** Two consecutive runs of unchanged code: 2026 ms and 2058 ms
(aggregate, ±1%); per route ±6–10%. Two routes with **no** code change moved by
−7.3% and −7.2% in the A/B below. Every claim in this report is sized against
that band.

## 4. Ranked findings

| # | Finding | Evidence | Impact | Fix | Risk | Result |
|---|---|---|---|---|---|---|
| 1 | `@supabase/supabase-js` (~66 kB gzip, auth + PostgREST + Realtime) was in the **shared shell bundle** of every signed-in page, pulled in by `AccountMenu → SignOutButton → lib/auth/client-actions → lib/supabase/client` | Chunk `3gtwt0vb0tbnj.js`, 259,446 B raw / 66.0 kB gzip, referenced by 12 of 15 audited routes | Largest client cost; downloaded by every page view to support a control that most views never use | Load the browser client with `await import()` inside the two async call sites (sign-out click handler, realtime-token effect) | Low — both call sites are already async; no API change | **Fixed**: −65.8 kB JS gzip on every app route (−27…−29 %) |
| 2 | A 104,896 B `logo.jpeg` was preloaded at image priority on **every** route for a 34 px decorative mark | `<link rel="preload" as="image" href="/_next/static/media/logo...jpeg">` on `/settings`, `/home`, etc. | 105 kB racing the stylesheet and text on a slow connection | `loading="lazy" fetchPriority="low"` on the mark (it is `aria-hidden`) | Low — decorative; box already reserved by width/height | **Fixed**: preload gone from all routes |
| 3 | The display font Boldonse (75,152 B) was declared in the root layout, so `next/font` preloaded it on all 70 routes while only `.login-title` uses it | `next-font-manifest.json`: 70/70 routes before, 2/70 after | 75 kB of unused preload per page | Move the `localFont()` declaration into `app/login/layout.js` | Low — CSS variable still reaches the login hero; verified `/login` still hints the face | **Fixed** |
| 4 | `/campus` ran a `communities` count that no caller rendered (`summary.communities` had no consumer) | Trace above: two `HEAD /communities`, only `clubs` is printed | One wasted round trip per visit | Drop the unused count from `getCampusSummary` | Very low — output field removed, no component reads it | **Fixed**: 14 → 13 requests |
| 5 | `.t-cinematic` was dead CSS referencing the display face | No element uses the class (grep) | ~0.4 kB of dead CSS; misleading coupling | Delete the rule | None | **Fixed** |
| 6 | `/market` issues 3 `HEAD marketplace_listings` + 1 full listing read | Trace: `HEAD` ×3 with different filters (active/reserved, free, sold) | 3 count queries; ~75 ms of parallel DB work, not serialized | — | Combining them needs an RPC or SQL change; forbidden here | **Deferred** (option in §7) |
| 7 | `/explore` reads `communities` twice | Two selects, `.eq('kind','community')` and `.eq('kind','club')`, both rendered | Two queries | — | They are genuinely different result sets; merging would not remove a round trip | **Not a defect** |
| 8 | `/chat` reads `conversation_members` twice | Own memberships, then all members of those conversations; both after `conversation_inbox` | 2 queries, parallel | — | Second read needs the first read's ids; parallel already | **Not a defect** |
| 9 | `rpc/trending_posts` is the slowest single query (89–138 ms) | Trace on `/explore` | Sets `/explore`'s floor | — | Needs SQL/index work with its own evidence | **Deferred** |
| 10 | One 205,708 B stylesheet (34,367 B gzip) is render-blocking on every route | `assets.mjs` | One blocking RTT; 34 kB | — | Splitting requires routing-level CSS architecture change | **Deferred** |
| 11 | `/home` HTML is 193.9 kB (109.5 kB RSC payload + 112.9 kB inline scripts) | `/tmp` payload split, `assets.mjs` `htmlBytes` | Bulk of remaining transfer | — | Trimming means fewer feed items (product change) or a different feed contract | **Deferred** |

Items 6–11 are listed with their evidence so a future pass can decide with data
rather than intuition; none was "fixed" by a speculative change.

## 5. Changes made

| File | Change |
|---|---|
| `lib/auth/client-actions.js` | `@supabase/supabase-js` is imported on demand (`loadBrowserClient()`); sign-out and realtime-token setup await it. Behaviour, error handling and ordering unchanged. |
| `components/brand/Brand.js` | Decorative logo: `loading="lazy"`, `fetchPriority="low"`, explicit width/height retained. |
| `app/layout.js` | Display font declaration removed from the root layout; only DM Mono remains global. |
| `app/login/layout.js` (new) | Owns the Boldonse `localFont`, so its preload exists only on `/login` and `/login/verify`. |
| `app/globals.css` | Removed the unused `.t-cinematic` rule. |
| `lib/data/campus.js` | `getCampusSummary` no longer counts unused `communities`; one query removed. |
| `scripts/dev/perf/measure.mjs` | Bug fix: reset the trace cursor after the warm-up request. Warm-up reads used to land inside the first measured sample, inflating single-run request counts (Campus hub showed 21 instead of 14). Medians were unaffected; single-run quotes were wrong. |
| `scripts/dev/perf/assets.mjs` (new) | Per-route client-payload measurement (modern scripts + preloads + stylesheets, raw and gzip). |

No route, component tree, permission, RLS rule, session check, design token or
copy was altered. No dependency was added (the two `perf:serve` packages stay
`--no-save`). No migration was touched.

**How to read this.** The only deterministic change here is `/campus`: one fewer

server-side regression observed, one real query removed, no evidence of a
systemic server speed-up from the client-side fixes** — which is expected, since
none of them touch rendering.

The genuine, attributable wins of this audit are in **transfer volume**: −65.8 kB
of JS (gzip) on every signed-in route and −180 kB of forced preload per page.

## 7. Remaining bottlenecks (ranked, with evidence)

1. **Identity chain is the per-page floor** — `auth /user` (27 ms) then
   `profile_private` (35 ms) serialize before any page data. Every route pays it.
   Fixing it means trusting JWT claims or caching identity across requests, both
   of which weaken the session model; **not recommended** without a security review.
2. **`/explore` — `rpc/trending_posts` 89–138 ms**, the single slowest query in
   the harness. Needs `EXPLAIN` evidence and possibly an index; index changes were
   out of scope here.
3. **Single render-blocking stylesheet** — 205,708 B raw / 34,367 B gzip for every
   route. Splitting it is a routing-architecture decision, not a safe tweak.
4. **HTML/RSC payload** — `/home` 193.9 kB (109.5 kB RSC + 112.9 kB inline
   scripts), `/profile` 192.7 kB. Reducing it means rendering fewer feed items or
   changing the feed contract.
5. **DM Mono preloaded everywhere** (90,092 B for two weights) for micro-labels.
   A subsetted build would help; it needs a font pipeline (new build dependency).
6. **`/market` three count queries** and **`/campus` remaining seven counts** could
   become one `count(*) FILTER` RPC each. That is an RPC contract change and needs
   its own review.
7. **No real-user monitoring.** Without Speed Insights (or an equivalent) on the
   live deployment, LCP/INP/CLS remain unmeasured. Enabling it is a product/ops
   decision and was deliberately **not** added — no analytics or tracking script
   was introduced by this task.
8. **Static-cacheable public pages** (`/legal`, `/rules`, `/timetable`) are
   rendered per request. Making them static is possible but changes cache and
   session semantics, so it is left as an option.
